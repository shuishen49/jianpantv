荐片 Windows C 桌面版 0.2.6

这是从安卓版 5.0.78 内置页面移植的非官方 Windows 客户端，宿主使用 C17、Win32 和微软 WebView2。没有采用旧 Windows 客户端，也没有打包 Android 运行环境。

发布目录包含 `Jianpian.exe` 和微软签名的 `WebView2Loader.dll`。两者都要保留，完整解压后运行 EXE。目标系统为 Windows 10/11 x64，并要求已有 Microsoft Edge WebView2 Runtime。程序不会自动安装运行环境。

播放页改为 TV 风格：左侧小播放器和缓存控制，右侧详情/讨论各自滚动。原有手机端固定在整个窗口底部的讨论输入栏已限制在讨论区。打开影片保持窗口模式；点击“全屏播放”或按 F11 放大，Esc 退出。900×640 的窗口也能查看完整讨论和选集。

0.2.6 使用新设计的透明播放图标，嵌入 16–256 像素九种尺寸，供 EXE、标题栏与任务栏使用；网页品牌区和 favicon 使用同一图标。原始生图、提示词及转换后的 PNG/ICO 位于 `windows-native/assets/`。工具栏改用原生绘制的小图标，页面统一深色与珊瑚红配色，改善侧栏对比度和搜索入口，并降低首页大图高度，使常用入口和影片列表更早出现。没有增加 UI 框架或运行库。

0.2.4 增加全屏左右方向键：← 快退 10 秒，→ 快进 10 秒，保持原来的播放/暂停状态，限制在视频可跳转范围内。输入框和带 Ctrl/Alt/Shift 的组合键保留原操作；捕获阶段处理并阻止同一次按键被原播放器重复处理。进入原生全屏时把键盘焦点交给播放器。

0.2.2 修复“请旋转手机观看”和 F11 仅放大窗口的问题。播放器内全屏按钮、下方“全屏播放”、原生工具栏及 F11 统一切换 Win32 全屏和播放器视口，移除手机方向锁及旋转回退。Esc、F11 和右上角“退出全屏 (Esc)”恢复小播放器。全屏不重新挂载或创建视频节点；比例保持，黑边由视频尺寸决定。回归检查覆盖 APK 中实际替换的进入、退出和尺寸变化函数；运行诊断同时断言播放器铺满视口、连续播放及退出还原，不能再仅凭窗口无边框判定全屏成功。

启动会弹出程序自己的“视频保存设置”，可以直接输入 `D:\jianpandownload` 等绝对路径。保存时递归创建不存在的目录，检查可写后原子保存设置；无效路径或创建失败时在弹窗内显示错误，不替换已有设置。工具栏“保存位置”可再次打开设置。播放列表直接保存在所填目录中，片段保存在其 `media` 子目录，不再额外套一层 `JianpianCache`。取消时沿用上次有效目录，首次取消则只在线播放。设置文件是 `%LOCALAPPDATA%\JianpianDesktop\video-directory-v2.txt`。升级会识别旧版 `video-directory.txt`，默认沿用其已有 `JianpianCache` 目录，不搬动旧文件。诊断烟测选择独立测试目录，不修改用户设置。

0.2.3 增加程序内更新。启动完成约 8 秒后在后台检查，保持运行时每 4 小时检查一次，也可点击工具栏“检查更新”。只读取本仓库的 Windows x64 更新清单；清单不可用时回退到 GitHub Release API，按数字版本比较并过滤 TV、草稿、旧版本、缺少校验值或更新附件的版本。Windows Release 目前使用 prerelease，因此不会简单采用仓库的 Latest（它可能是 TV 版）。

发现新版先显示当前版本、新版和下载大小，询问是否下载并安装，默认选择“否”。确认后才下载 EXE；下载期间仍可使用。校验下载大小、SHA-256、x64 PE 及嵌入的版本/微软加载器摘要契约，确认后启动同目录的临时原生更新进程。更新进程等待原程序退出，使用 ReplaceFile 替换 EXE，保留旧版，启动新版并等待 WebView2 创建成功的握手；失败时还原并重启旧版。新进程成功启动后移除旧版和临时更新进程，不更改视频缓存、设置和微软 DLL。安装会停止当前播放和下载任务。更新不执行 PowerShell、批处理、远程脚本，也不申请管理员权限。程序目录不可写、微软加载器版本变化或文件检查失败时，应重新完整解压便携包。

这是需要重启的程序内更新，不是在运行中替换代码。0.2.2 及更早版本没有检查功能，必须先手动安装一次 0.2.3。自动更新附件 `Jianpian-Windows-C-<版本>.exe` 由已校验的便携包原样复制；首次安装使用 ZIP，以保留微软 DLL。固定更新清单位于 `updates/windows-x64.json`，只在 GitHub Release 发布并验证成功后随源码同步到主分支。未来发布同样必须提供 EXE 附件并更新此清单。

播放期间的 HTTPS HLS 片段经过原生代理并持久保存，相同 URL 和 Range 的请求复用本地片段。缓存键由完整 URL 和 Range 的 SHA-256 构成，不把服务响应当作文件路径。`.ts` 保存原始媒体字节，`.info` 保存响应元数据和内容校验值；不转码。写入临时文件、刷盘后原子发布；长度、校验或元数据不完整时回源。API 响应、错误页面和播放清单不持久缓存，避免过期服务数据和媒体链接。

“缓存整集（MP4）”遍历当前普通 HLS 点播清单，依次获取媒体、初始化片段和 AES-128 密钥，同时允许继续播放。全部片段成功保存后生成供合并使用的本地清单，在独立线程中通过裁剪编译的 FFmpeg C 容器库无重编码合并为单个 MP4。支持单独复制、移动和播放。只有完成尾部索引、刷盘和原子发布后才显示“已保存为 MP4”，随后删除本次临时 m3u8。已有旧版 m3u8 不会在升级时自动批量转换；重新点保存可复用地址和范围匹配的完整缓存。

0.2.6 的成品命名为 `《八仙！》-1080p-国语.mp4`；语言缺失或未知时省略，剧集包含已知集数，例如 `《三体》-第01集-1080p-国语.mp4`。名称不含“荐片”前缀或地址摘要。片名、集数和语言在开始下载时确定，避免下载过程中切换页面导致串名；优先使用所选音轨语言，其次影片的语言字段，必要时读取媒体内明确的音轨语言，不从地区推测语言。常见语言代码转换为中文名称。

清晰度取实际媒体画面短边像素数，不使用播放器当前显示尺寸或未经确认的“高清”标签。存在不同分辨率的切换片段时，按各分辨率的累计时长选择主要规格；无法读取时省略。同名文件原子发布时不覆盖，依次另存为 ` (2)`、` (3)` 等后缀。Windows 非法字符会替换，过长名称安全截短并保留扩展名。旧的成品文件不因升级而自动重命名。

0.2.5 修复含 `EXT-X-DISCONTINUITY` 的 HLS 合并失败：每个声明的连续区间单独解封装，再按清单时长接回同一个 MP4 时间轴。这样允许切换点的 TS 计数器及时间戳重新开始，也处理插入片段结束后的时间戳前跳。各区间继承有效密钥、初始化段和原始媒体序号，保留 AES-128 隐式 IV。AAC 配置变化写入 MP4 样本描述。没有改写原始分片、忽略损坏标记或删去插入片段；校验失败、未声明的传输错误及不完整时长仍拒绝发布。错误信息显示出错阶段、包信息或时长差异。

合并器只读取当前清单列出的 media/摘要.ts 文件，逐个核对缓存 SHA-256，FFmpeg 编译时关闭网络、解码器、编码器及无关格式。普通 H.264/AAC TS 和初始化分片通过短样本验证；AES-128 先按清单解密再封装，音视频参数只从压缩头读取。使用包内时间戳、时基和 DTS/PTS 差值，处理时间戳重置并检查实际输出时长，缺失、损坏、格式不支持或时长明显不符时不发布成功。取消、关闭和保存目录变化会停止合并，清理本次 partial，保留旧 MP4 和已完成分片。没有后台常驻下载或本地影片库。

0.2.6 在完整 MP4 刷盘、原子发布且合并器关闭输入文件后，自动删除本集临时 m3u8 及对应的 `.ts` / `.info`，media 为空时删除空目录。清理与缓存读写使用同一锁；已经读入的播放响应继续有效，本次运行中返回较晚的网络响应不再写回已完成的分片。之后重新播放仍可能需要联网；成品 MP4 可单独离线打开，程序暂未提供影片库入口。

其他未完成下载的 m3u8 或 `.jp-download` 清单会保护其引用的共用分片。被占用或共用的文件通过小型 `.jp-cleanup` 记录稍后重试，并在下次选择此目录时恢复；对应 MP4 不存在或大小变化时保留分片。只删除本集摘要列表内、具有本程序缓存元数据的文件，不递归清空目录，也不跟随 media 或文件的重解析点。失败或停止不会清理恢复用缓存；用户明确重新保存同一集时允许重新写入。权限导致无法创建恢复记录时，界面明确提示检查权限并重新保存。多个客户端进程同时使用一个目录尚未验证。

直播、独立音轨、字节范围 HLS、DRM 和原版 P2P 下载内核不在整集保存支持范围。运行时会明确提示。普通播放仍按现有线路处理。重试时如果上游更换签名 URL，缓存按新地址重新下载；不推测不同地址是同一媒体。直连 MP4 不走这一 HLS 保存流程。

实测范围见 `testing/windows-native-0.2.6/verification.json` 与 `mp4-verification.json`。28 项 MP4 检查覆盖音视频包数/时长、AES-128、跨区间密钥/隐式 IV/初始化段继承、原始计数器重置、时间戳先后退再前跳、未声明的传输错误、区间内部丢包与 TEI、摘要损坏、缺片、路径、时长、取消、成品命名和重名保留，并覆盖成功清理、失败/取消保留。61 项 cleanup-test 使用实际文件锁和并发读写，检查共用下载、晚到写入、显式重试、新旧文件名的恢复记录以及无成品时保留缓存。另有 28 项 Unicode 命名/元数据边界检查、25 项下载及 APK 实际标题渲染检查。九种尺寸的图标资源逐个核对，确认与源码 ICO 一致。

`saved-vod-verification.json` 保留此前 0.2.6 开发构建的 372 分片整集隔离验证记录及其原 EXE 摘要，属于明确标注的历史记录，未冒充最终图标/命名构建的重测。该记录核对约 24 分 45 秒时长和包数，在切换点前后及片尾通过 Windows 系统解码和跳转，随后自动清理测试副本的缓存。最终构建重新运行上述短样本和在线播放、布局、全屏与缓存检查。没有逐帧解码或人工看完整集，不分发测试媒体，不宣称已验证全部编码格式。

程序目录的体积和运行后的用户数据体积是两项不同数据。程序复用本机 WebView2，用户数据位于 `%LOCALAPPDATA%\JianpianDesktop\NativeWebView2`，包含浏览器的安全组件和缓存，后续会随使用变化。启动参数对浏览器磁盘缓存和媒体缓存各请求 8 MiB 的预算，这不是整个用户数据目录的大小上限。

安全处理包括运行时加载器 SHA-256 校验、标准 HTTPS 证书验证、媒体代理对内网地址的检查、请求与响应大小限制、并发限制，以及对网页下载、外部页面、外部协议、子框架和敏感权限的限制。更新仅使用固定仓库和 GitHub 的 HTTPS 附件域名，显式验证跳转，不转发凭证。更新清单及校验值信任此 GitHub 仓库的维护者，不等于独立数字签名。没有添加开机自启、关闭杀毒或执行系统命令的功能。远程业务和媒体内容依赖原有服务。

最终交付的 EXE 没有 Authenticode 签名。微软 DLL 的签名和 Defender 的扫描结果单独记录，不能以 APK 或早期版本的检测结果替代最终文件的检测结果。

构建使用 Python 3、Zig 0.14.1 的 C 编译器和官方 Microsoft.Web.WebView2 1.0.4314.35 NuGet SDK。编译器和开发 SDK 仅用于构建，不放入运行包。源代码不是 Zig 语言。构建脚本固定校验 APK、其内置网页包和 SDK 安装包的 SHA-256。

在工作区根目录运行：

```powershell
# 先将官方 FFmpeg 9.0.2 源码放入 tools/ffmpeg-9.0.2，
# 并保留其 tar.xz、官方签名和公钥。build_remux.py 固定核对归档 SHA-256。
python .\windows-native\build_remux.py
python .\windows-native\build_native.py
```

所需文件位置：

- 原版 APK：`handoff/apks/mobile-5.0.78.apk`
- WebView2 SDK：`tools/webview2/`
- 便携编译器：`tools/zig-x86_64-windows-0.14.1/zig.exe`
- 共用桌面样式：`windows-desktop/desktop.css`
- FFmpeg 原版源码包：`tools/ffmpeg-9.0.2.tar.xz`，SHA-256 `8c3850283eb25fa026482078a04051e0be17347b09ef81a0849bec15a96e002e`
- FFmpeg 官方签名指纹：`FCF986EA15E6E293A5644F10B4322F04D67658D8`，应对照官方公布指纹检查 detached signature
- 构建容器库使用 Git for Windows 的 bash 和 `tools/make/mingw64/bin/mingw32-make.exe`；GNU make 及其 gettext/libiconv 仅用于构建

FFmpeg 仅开启 HLS/MPEG-TS/MOV/AAC/AC3 容器读取、MP4 写入、相关压缩头解析及 AES 文件协议，不包含 FFmpeg 命令行程序、网络协议、解码器或编码器。配置见 `build_remux.py` 和构建清单。FFmpeg 的 LGPL-2.1-or-later 许可和原作者版权仍适用，许可证随运行包提供。

源码与检查包包含未修改的完整 FFmpeg 源码归档、签名/公钥、实际构建配置、三个静态库、宿主和合并器对象以及包含界面资源的 app.res。将其解压后可使用修改后的 FFmpeg 库重新链接，无需原始 APK：

```powershell
python .\relink\relink.py --compiler D:\path\to\zig.exe --libraries .\relink --output .\Jianpian-relinked.exe
```

`--libraries` 指向替换后的 libavformat.a、libavcodec.a 和 libavutil.a；保持与 FFmpeg 9.0.2 的 ABI 及 x64 Windows GNU 目标兼容。将重链 EXE 与微软 DLL 放在同目录运行。MP4 短样本检查：`python windows-native/check_remux.py --fixture D:\path\to\short-h264-aac.ts`。已有完整缓存的隔离复现：`python windows-native/check_remux_saved.py D:\video-directory 64位清单摘要 --seek 1 298 300 318`；脚本先复制到工作区，不修改原缓存，测试媒体由复现者自行提供。

构建清单在 `work/windows-native-build/build-inventory.json`，包含输入文件、网页资源、EXE 和 DLL 的哈希。代码的 Android 目标替换、HLS 缓冲限制、CSP 调整、标题和桌面样式补充都在构建脚本中明确列出。

验证命令：

```powershell
# 使用构建命令记录中的同一编译器和 SDK 编译测试。
python .\windows-native\build_tests.py
python .\windows-native\verify_native.py --binary-only

# 启动有界的访客诊断；不登录账号，不录入账号信息。
.\output\Jianpian-Windows-C-0.2.6\Jianpian.exe --diagnostics D:\source_code\jianpian\testing\windows-native-0.2.6 --smoke-test

# 诊断完成后检查真实页面、解码进度、暂停、跳转、全屏和返回首页。
python .\windows-native\verify_native.py
```

`--verify-runtime <JSON路径>` 只校验同目录的微软 DLL 并退出，不加载该 DLL、不创建浏览器。该入口用于验证缺失和被修改的加载器会被拒绝。

`--check-updates <JSON路径>` 使用真实 GitHub 更新源记录当前版本、是否有可自动安装的新版、HTTP 状态及更新文件摘要，然后退出，不显示提示、不下载 EXE。诊断模式不会自动检查更新，避免干扰播放烟测。
