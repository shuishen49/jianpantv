# tv.12 索尼全屏黑屏修复候选

日期：2026-11-07。源码基线：`965c3cdad9b881aabb3f4e6172cae17c29b246e3`。

## 已观察到的现象

索尼 BRAVIA 4K GB、Android 9（API 28）、ARM32、1920×1080。
同一视频在 tv.11 的详情页小窗口中有连续画面，点击“全屏播放”后黑屏。
播放日志显示已启动 `OMX.MTK.VIDEO.DECODER.AVC`；
全屏时的原生视图树显示 PlayerView 和 TextureView 均为可见、1920×1080。

以上证据更支持全屏显示路径问题，尚未完整排除电视厂商的合成兼容性问题。
不能仅凭这些观察断言所有视频的解码都正常。
本次没有添加软件解码器，也没有强制更换视频编码或解码组件。

## 修复内容

1. 全屏时让原生 WebView 使用透明 ARGB 背景，并保持硬件合成；
   即使原网页随后请求不透明背景，全屏控制界面也不会因此覆盖下层视频。
   退出全屏恢复最近一次原网页请求的背景设置，不修改登录、接口或证书逻辑。
2. 全屏期间只改变 WebView 与视频的显示顺序和 Z 值，不移除再添加视频视图；
   从全屏返回时也使用 `bringToFront()`，避免由移除视频视图触发
   TextureView/SurfaceTexture 的销毁与重建。
3. 明确把全屏播放器壳及原生视频占位区设为透明，并清零壳的内边距。
   错误提示、加载提示和进度条保留原有显示。
4. 保留原有 UMeng 移除、包内运行时冻结、无共享存储权限等安全修改。

修改由 `fullscreen_patch_tv.py`、`build_mobile_tv.py` 和电视 CSS 参与实际构建。
`patched/` 与旧清单仍是 tv.11 的历史审阅快照；tv.12 构建后的实际 smali 位于
`work/mobile-tv12`。

## 安装与测试

本机缺少已安装 tv.11 的原签名密钥，因此生成独立包：

- 版本：`5.0.78-tv.12` / `5090`
- 包名：`local.tv.jianpiansonytest`
- 桌面名称：`荐片·索尼全屏测试`
- APK：`output/jianpian-mobile-tv-5.0.78-tv.12.apk`
- SHA-256：`f86f16ca267fc341ec98d52276fef8f236d70ec8213992cb7dabe1d3cd6154df`
- 签名 SHA-256：`f16177462b86ed9e88fc6d11b34dcb8b0c129c8589e698af677c8ef446307efb`

此包与 tv.11 共存，不覆盖或迁移 tv.11 的数据。首次打开需要单独登录。
本地新签名保存在忽略目录 `.local-signing/`，未包含在交付文件中。

建议真机测试：

1. 安装后打开“荐片·索尼全屏测试”，登录并播放刚才黑屏的同一部视频。
2. 先确认小窗口有画面，再进入全屏；等进度条隐藏后观察画面。
3. 测试暂停、继续、快进十秒和快退十秒。
4. 返回小窗口，再连续切换全屏三次，确认画面正常且进度继续。
5. 换一集或另一条线路复测；再次返回列表确认播放停止。

如仍黑屏，请区分：小窗口是否正常、全屏是否有声音、能否显示进度条、
切回小窗口是否立即恢复，以及具体线路。它们有助于区分遮挡、合成与解码问题。
